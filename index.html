The workflow

GitHub is the queue.
Your Mac is the workforce.

Rosetta turns the tools your team already trusts into a durable operating loop—without hiding the work inside another dashboard.

01 Signal

Write the outcome.

Open a GitHub issue with acceptance criteria and apply agent:ready. That issue becomes the source of truth.

02 Isolate

Protect the checkout.

Rosetta verifies the author, claims the work, and creates a dedicated branch and worktree for the run.

03 Execute

Match the right agent.

Builder, researcher, and reviewer profiles give each issue the right operating posture and tool access.

04 Review

Keep humans in control.

Verified changes return through a pull request, with issue comments and history preserved as the durable record.

Deliberate by design

Automation that respects the boundary.

Rosetta’s control plane is intentionally small. Agents do the creative work; a deterministic local service owns the lifecycle around it.

✓

01 / AUTHORSHIP

Owner-authorized work only.

The service verifies the issue author before an agent can claim or execute the task.

02 / CONTAINMENT

Every run gets a boundary.

Dedicated worktrees and workspace-scoped execution keep parallel changes isolated and reviewable.

03 / AUDIT

GitHub keeps the receipt.

Issues, pull requests, labels, and comments preserve a record that teammates can inspect later.
